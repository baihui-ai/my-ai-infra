## 一、多视口与整页视觉自动化验收清单（阶段 4 必跑）

### 1. 必测视口矩阵（不标视口的首屏结论一律作废）
- **PC 桌面端（5 档全测）**：
  - **`2560×1320`**（27 寸 2K/4K 大屏浏览器窗口——专查大屏首屏「假底纯白空带（False Floor）」与超宽屏比例失衡）
  - `1920×1080`（默认全高清宽屏）
  - **`1920×920`**（扣除浏览器顶栏、书签栏与 Windows 任务栏约 130–160px 后的真实可视高度——48%+ 桌面访客在此视口，首屏核心信息与主按钮**绝不能被截断**）
  - `1440×900`（常见笔记本）
  - `1366×768`（办公电脑常见下限，决定首屏内容上限）
- **移动端（2 档全测，仅在改移动或响应式验收时）**：
  - `390×660`（iPhone 真实 Safari 可视区）
  - `360×800`（主流安卓下限）
- **实测要求**：调用浏览器工具先 `resize_window` 后必须回读 `window.innerWidth` 与 `document.documentElement.scrollWidth` 核验。

### 2. 自动化样式盘点 8 项必过门槛
1. **横向溢出**：全部目标视口 `scrollWidth <= innerWidth`（严格 `0 px` 溢出）。
2. **文字对比度**：正文与次要说明文字全部满足 WCAG 2.2 第 1.4.3 条 **≥ 4.5:1**（重点查灰底上的浅灰字，0 处不达标）。
3. **字号与眉题收敛**：整页可见字号种类控制在合理阶梯（参考标杆 5–10 种，复杂页 ≤ 15 种）；同级板块眉题、卡片标题、文字链接样式完全统一，无层级倒挂。
4. **内容零丢失**：整页改版前后若要求文案一致，通过脚本对比 `textContent` 逐字一致；确认无遗留说明标签、无 `target="_blank"` 误留。
5. **眯眼视觉重心测试**：生成整页缩略模糊图，检查核心信任/转化区是否视觉权重足够、无头重脚轻。
6. **初始 HTML 直出核验（SEO 红线）**：核心文案、规格表、完整多级面包屑与 `BreadcrumbList` / `Product` 结构化数据 100% 位于初始 HTML DOM 内，禁止依赖 JS 异步渲染才出现。
7. **键盘与无障碍**：页头下拉不支持仅靠鼠标打开（Tab 走主项、Enter 进总页、Space/↓ 展开下拉、Esc 收起并归还焦点、`aria-expanded` 正确、焦点框 ≥ 3px 可见）；装饰图标 `alt=""`，Logo `alt="LILY Bearing"`。
8. **图片、懒加载与脚本体积**：图片按显示宽 2 倍导出 WebP；自动化核查破图前**必须先分段滚扫全页触发 `loading="lazy"` 图片加载**防误报；无 `<!DOCTYPE html>` 缺失；设计稿内覆盖式旧 CSS 须在交接单明示由研发按统一 Tokens 重写。
9. **大屏防假底、悬浮导航与交互浮层专项核验（2026-11-24 升级）**：① **防假底（False Floor）量化校验**：在 `2560×1320`、`1920×1080`、`1920×920`、`1440×900`、`1366×768` 五档桌面均须实测 `deadBlankStripPx`（首屏底沿至下一板块真实可见文字间的空白带），严禁首屏固定封顶（如 `min(100vh, 980px)`）叠加下屏 `padding-top: 108px` 与 `align-items: end` 造出 >40px 纯白假底——采用「全分辨率露头窥视」时须核验 5 档全部 `h2VisibleAboveFold === true` 且 `deadBlankStripPx ≤ 40px`；② 若首屏采用透明悬浮顶栏，默认 CSS 须确保加载首帧即透明零蓝闪（如 `body:not(.hm-scrolled)`），并实拍中段滚动（如 `y=560`）验证顶栏在首屏控件靠近前已切回实体防重叠；③ 搜索框展开联想浮层须实拍验证 `z-index` 高于相邻板块且不被视口底部裁切，列表内严禁混入类目导航链接；④ 若微控件配色／材质或首屏衔接有主观取舍分歧，优先产出「同帧单变量实景对比页」供决策人一屏拍板。

## 二、行为闭环切片与研发开工交接单模板（阶段 5 必备）

复杂改版严禁一次性混在一起开发，必须切分为 **切片 0（阻断热修，不跑 AB）** 和 **切片 1（核心重构，跑 50/50 服务端 AB）**。每个切片必须写齐 **6 要素**：
1. 用户／系统可观察行为变化
2. 代码与文件边界
3. 明确排除范围（**必须单列线上在测实验隔离清单**）
4. 验收方法（具体视口、真页 URL、BigQuery/HubSpot 核验动作）
5. 审查重点（最易出回归或污染的风险点）
6. 前置依赖

### 研发开工交接单固定 6 节结构
1. **置顶红线**：① 上线严禁覆盖老版，必须 50/50 服务端无闪烁 AB（写明 Bucketeer 实验名与分流键 `track_id`）；② 绝对不触碰的线上在测实验清单及对应 JS/DOM 名单；③ 仅英文主站（`en-us`）先行，不动多语言表单。
2. **前端与视觉契约**：锁定色板、组件三态（中国仓/美仓/无价）、吸顶/抽屉交互、初始 DOM 要求。
3. **后端、表单打分与性能减负**：所有新表单必须带 7 个来源与访客隐藏字段、接入 HubSpot AI 打分与销售路由并命名规范（禁用“联调”字样）；非首屏阻塞脚本异步/按需加载。
4. **动态数据取数契约（若涉多类目/全库料号）**：必须写明多级降级规则（如 L1 Top 20 精调白名单 → L2 规则滤空 → L3 表头清洗与同义去重 → L4 兜底＋短标签映射），并实检至少 20 个主力类目真实商品防脏数据。
5. **埋点契约（接入 `dwd_quick_tracking_event_slim`）**：补齐本轮核心交互事件、真实性能 `web_vitals`（LCP/INP/CLS）及支付设备归属 `client_platform`。
6. **上线前必过测试清单 ＋ 放量/回滚门槛**。

## 三、双轨 AB 验证与放量模型（阶段 6）

### 轨道 A：大样本页面（首页、全站导航、桌面详情页等）—「三层分工制」
判胜铁律：**主裁判显著胜出 ＋ 护栏未掉坑 ＋ 总账净增**（三层不直接相加）：

| 层级 | 监控对象 | 作用 |
|---|---|---|
| **第一层·主裁判区** | 本页改版核心目标组件产生的提交/进入量、**4 分+ 高质量询盘**（不含 4.1）及线索质量结构（3.0+ / 0 分占比） | 保持归因纯度，不被旁路噪声稀释 |
| **第二层·旁路与护栏区** | **4.1 Shopify 实付订单**笔数与金额、在线 Chat 留邮箱量及 4 分+、跳去报价/联系页填表量；对离线复制邮箱固定标口径盲区 | 防“左手倒右手”挤占或逼走在线买家 |
| **第三层·公司总账区** | 全站 4 分+ 高质量总询盘（不含 4.1，表单＋Chat 去重）与全站总询盘 | 确认公司全局净增量 |

### 轨道 B：小样本页面（如月均填表 < 50 单的移动端详情页）—「14 天 50/50 护栏灰度」
不苦等数月常规双侧显著性，满 **14 天** 核验以下 4 项即决策：
1. **信任护栏**：干净样本分流均衡检验（SRM）`p > 0.01`；Sentry 新增报错 = 0；表单 HubSpot 打分非空率 = 100%。
2. **主判指标（上游复合意向）**：复合意向触发率（开始填表 ∪ 加购 ∪ 复制型号 ∪ 下图纸 去重）实验组相对对照组持平或正向。
3. **商业底线护栏（非劣效）**：实验组「表单提交＋实付真单合计率」单侧 90% 置信下限不低于对照组 80%，无连续 5 天归零或腰斩。
4. **体验护栏**：客户端实测 `LCP P75 ≤ 2.5s`、`INP P75 ≤ 200ms`、`CLS P75 ≤ 0.1`；抽查 20 段 Clarity 美国录屏确认无死点击与遮挡。
- **放量后追踪**：达标即 100% 全量释放，第 28 天与第 60 天复核谷歌 CrUX 现场性能与 GSC 同页双端排名/点击率差值；任意护栏触发红线立即 Bucketeer 一键切回 0%。
