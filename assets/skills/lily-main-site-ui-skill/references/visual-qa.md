## 一、多视口与整页视觉自动化验收清单（阶段 4 必跑）

### 1. 必测视口矩阵（不标视口的首屏结论一律作废）
- **PC 桌面端（5 档全测）**：
  - **`2560×1320`**（27 寸 2K/4K 大屏浏览器窗口——专查大屏首屏「假底纯白空带（False Floor）」与超宽屏比例失衡）
  - `1920×1080`（默认全高清宽屏）
  - **`1920×920`**（扣除浏览器顶栏、书签栏与 Windows 任务栏约 130–160px 后的真实可视高度——48%+ 桌面访客在此视口，首屏核心信息与主按钮**绝不能被截断**）
  - `1440×900`（常见笔记本）
  - `1366×768`（办公电脑常见下限，决定首屏内容上限）
- **移动端（2 档全测，仅在改移动或响应式验收时）**：
  - `390×660`（iPhone 真实 Safari 可视区）
  - `360×800`（主流安卓下限）
- **实测要求**：调用浏览器工具先 `resize_window` 后必须回读 `window.innerWidth` 与 `document.documentElement.scrollWidth` 核验。

### 2. 自动化样式盘点 8 项必过门槛
1. **横向溢出**：全部目标视口 `scrollWidth <= innerWidth`（严格 `0 px` 溢出）。
2. **文字对比度**：正文与次要说明文字全部满足 WCAG 2.2 第 1.4.3 条 **≥ 4.5:1**（重点查灰底上的浅灰字，0 处不达标）。
3. **字号与眉题收敛**：整页可见字号种类控制在合理阶梯（参考标杆 5–10 种，复杂页 ≤ 15 种）；同级板块眉题、卡片标题、文字链接样式完全统一，无层级倒挂。
4. **内容零丢失**：整页改版前后若要求文案一致，通过脚本对比 `textContent` 逐字一致；确认无遗留说明标签、无 `target="_blank"` 误留。
5. **眯眼视觉重心测试**：生成整页缩略模糊图，检查核心信任/转化区是否视觉权重足够、无头重脚轻。
6. **初始 HTML 直出核验（SEO 红线）**：核心文案、规格表、完整多级面包屑与 `BreadcrumbList` / `Product` 结构化数据 100% 位于初始 HTML DOM 内，禁止依赖 JS 异步渲染才出现。
7. **键盘与无障碍**：页头下拉不支持仅靠鼠标打开（Tab 走主项、Enter 进总页、Space/↓ 展开下拉、Esc 收起并归还焦点、`aria-expanded` 正确、焦点框 ≥ 3px 可见）；装饰图标 `alt=""`，Logo `alt="LILY Bearing"`。
8. **图片、懒加载与脚本体积**：图片按显示宽 2 倍导出 WebP；自动化核查破图前**必须先分段滚扫全页触发 `loading="lazy"` 图片加载**防误报；无 `<!DOCTYPE html>` 缺失；设计稿内覆盖式旧 CSS 须在交接单明示由研发按统一 Tokens 重写。
9. **大屏防假底、悬浮导航与交互浮层专项核验（2026-11-24 升级）**：① **防假底（False Floor）量化校验**：在 `2560×1320`、`1920×1080`、`1920×920`、`1440×900`、`1366×768` 五档桌面均须实测 `deadBlankStripPx`（首屏底沿至下一板块真实可见文字间的空白带），严禁首屏固定封顶（如 `min(100vh, 980px)`）叠加下屏 `padding-top: 108px` 与 `align-items: end` 造出 >40px 纯白假底——采用「全分辨率露头窥视」时须核验 5 档全部 `h2VisibleAboveFold === true` 且 `deadBlankStripPx ≤ 40px`；② 若首屏采用透明悬浮顶栏，默认 CSS 须确保加载首帧即透明零蓝闪（如 `body:not(.hm-scrolled)`），并实拍中段滚动（如 `y=560`）验证顶栏在首屏控件靠近前已切回实体防重叠；③ 搜索框展开联想浮层须实拍验证 `z-index` 高于相邻板块且不被视口底部裁切，列表内严禁混入类目导航链接；④ 若微控件配色／材质或首屏衔接有主观取舍分歧，优先产出「同帧单变量实景对比页」供决策人一屏拍板。
