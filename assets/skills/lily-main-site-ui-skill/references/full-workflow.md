# 网页设计标准流程（lily-main-site-ui-skill v0.3）

> **适用范围**：LILY Bearing（`lily-bearing.com`）所有页面改版、新建落地页及核心组件 AB 优化。默认英文主站（`en-us`）先行，验证后再议多语言。
> **核心铁律**：页面设计与交互判断**依次以用户数据、美国用户习惯、转化率为准，不以个人主观审美为准**；设计者或负责人提供的业务事实照用，但设计判断必须用数据交叉核验。

---

## 一、同事与本机双轨输入模式（开工先自检）

开工前先检查当前环境是否具备实时数据连接（MCP）：
- **直连模式（已接 lily / Clarity / HubSpot / ahrefs / 飞书）**：按各阶段要求直接只读拉数，并在汇报首行写明「数据依据」（已查哪几路、未查哪几路及原因）。
- **导数投喂模式（无 MCP 权限的同事使用）**：暂停并输出最小导数清单，请同事上传/贴入脱敏汇总表后再继续，**严禁在缺数据时拍脑袋画原型**：
  1. 近 30 天该页分设备（桌面/移动）访客、停留、跳出与核心转化统计（以 lily 自有埋点为准，勿直接拿未剔除爬虫的 GA4 原始会话）；
  2. Clarity 该页近 30 天死点击、狂点、滚动深度截图或摘要；
  3. GSC 该页近 28 天 Top 30 搜索词（区分品牌词/非品牌词）与分设备点击率；
  4. 线上页面 URL 及目标改版范围说明。
- **脱敏红线**：面向普通同事共享或跨外部工具传输时，严禁包含未脱敏的客户原始邮箱、电话、具体公司全名或财务明细。

## 二、七阶段闭环主流程与 4 个人工决策闸口

必须按顺序推进；**每个闸口（G1–G4）必须停下等负责人／主管拍板**，其余环节由 AI 标准化跑完。

### 阶段 0：立项定界与冲突排查
1. 明确本轮「改什么」与「明确不改什么」（语言站、终端主口径、哪些既有页面/网址保留不删）。
2. **线上在测实验隔离核查**：查当前全站正在运行的 AB 实验（如 `prod-navigation-page`、`prod-detail-quote`、`prod-mobile-pdp-v1` 等）及其触发条件与脚本，写明本轮绝不能触碰的 DOM 与 JS 文件边界。
3. 查历史决策日志（`docs/decisions-log.md`）、相关会议纪要与飞书待办，防止推翻已定口径。
4. **交付**：《改版范围与隔离边界清单》。
5. **🔴 闸口 G1（人工确认）**：确认语言站范围、主次终端口径、线上实验隔离方式及本次改版第一业务目标。

### 阶段 1：多源底数诊断与用户画像（禁止先画图）
1. **拉取同口径底数**：
   - `lily` 自有埋点（BigQuery `dwd_quick_tracking_event_slim`，剔除机器与机房流量，**严格拆桌面端/移动端、拆美国/非美国**）：查进站流量来源、首屏/各区块点击分布、站内搜索占比、去向路径、表单/Chat/加购/实付真单转化。
   - `Clarity`（同期同设备）：查死点击、狂点、快速返回、滚动深度，定位需看录屏的具体卡点（⚠️ **调用铁律**：Clarity `query-analytics-dashboard` 每次只能查**单个指标**，多指标合并会触发 `HTTP 500`；查根域名首页 `https://www.lily-bearing.com/` 时勿直接做 URL 过滤［会被当成全站前缀匹配］，须查 `Top 50 visited URLs with dead clicks / quick backs` 排行表再精确取首页那一行）。
   - `GSC`（近 28 天）：查该页自然搜索展现、点击、CTR、平均排名及词类结构（品牌词 vs 品类词 vs 型号词）。
   - `HubSpot` / 客户来信语料（按需）：回答「**来这个页面的人手里拿着什么、最常问什么**」。
   - `线上源码与性能`（`get_page_seo` / `get_page_html`）：核对 H1、结构化数据、脚本体积、移动端/桌面端 DOM 结构与明显阻断 Bug。
2. **因果与样本核查**：严防幸存者偏差（如只看留了邮箱的人忽略未转化流失访客）和因果倒置（如把“落地页差导致广告收预算”误判为“品类没流量不值得做”）。
3. **交付**：《底数对账与问题诊断单》（把问题明确切分为 **P0 阻断缺陷** vs **体验与转化结构问题**）。

### 阶段 2：双轨合标对标遴选与需求深挖
1. 严格按 [benchmark-and-copy.md](benchmark-and-copy.md) 按页面定位分轨挑选 **5 家合标对标站**，用 Ahrefs 核验美国谷歌月自然访问量（必须 > 2 万）：
   - **品牌旗舰页（首页、About Us）**：优先对标高水准美国高精尖科技／航空／机器人硬件制造商（如 Anduril、Samsara、Verkada、Skydio、Formlabs、Boston Dynamics），塑造制造企业调性与质感，**不照搬平台目录站样式**；
   - **目录／找货页（类目页、词根页、详情页）**：优先对标 McMaster-Carr、米思米（MISUMI）及高自然流量零部件目录站。
2. **只给对标网址＋关键做法对比表，不发截图**（由决策人自己点开一眼淘汰“陈旧站”）。
3. 按业务目标做需求深挖（复杂页面建议先过 `/deeper`）：锁定该页唯一核心任务、逐模块做「存在必要性」拷问（能删则删，不重复堆砌全站已有入口），并定下上线后的成功标准与观测指标。
4. **🔴 闸口 G2（人工确认）**：确认采纳的对标参考点、页面核心定位及逐模块增删清单。

### 阶段 3：纯真原型逐版迭代（去噪＋真数据＋单变量盲选）
1. 严格读取并锁定 [design-tokens.md](design-tokens.md)（全站第 36 版色板、品牌饱和度边界锁、按钮颜色语义、字号阶梯、认证印章合规、环境视频规范与纯 To B 调性）。
2. 输出**正式英文可交互 HTML 原型**：
   - **页面本体绝对纯净**：不放说明标签、不放浮窗注释、不放占位提示文字（免干扰肉眼判断），占位图仅留规范空框；所有设计理由、数据依据和待补拍素材另写同名 `*_说明.md`。
   - **全库真素材与真口径**：开工前完整盘点本地高清图库与最新 1080p 视频原片（不拿单条旧素材硬撑全页）；跨页业务口径须与 `About Us` 定稿逐项对齐（涵盖轴承、航空件、传动件三大产品线；严禁把内部渠道/利润占比口径写成对外文案）；涉及交易/履约的页面完整呈现三态（中国仓常规有价 / 美国亚马逊仓现货 / 无价定制）。
   - **单变量 8 方案实景对比墙（高审美敏感微控件必用）**：遇到按钮配色、蒙版深度、卡片材质等依赖人眼直觉的微调，**严禁每猜一色就反复重出整版原型**——直接锁死同一真实画面输出 1 页「单变量 5–8 方案实景对照板」（支持点击 1:1 放大与数字键秒切），让决策人一次横比拍板。
   - **AB 对照铁律**：若设计 A/B 两版，除实验核心变量（如首屏模块）外，其余区块必须逐字一致。
3. 每次修改保留版本号（如 `v1`、`v2`…），不覆盖旧版定稿。
4. **🔴 闸口 G3（人工确认）**：决策人按真实使用场景在目标视口亲手试操作并定版。

### 阶段 4：整页视觉审查与多视口自动化验收
1. 严格按 [qa-and-ab-playbook.md](qa-and-ab-playbook.md) 用真实无头浏览器跑自动化盘点：
   - **PC 桌面端必测 5 档（含 2K 大屏防假底）**：`2560×1320`（27 寸 2K/4K 大屏浏览器）、`1920×1080`、`1920×920`（扣除浏览器栏与 Windows 任务栏的真实可视高度）、`1440×900`、`1366×768`，截图必标视口并用 `window.innerWidth` 回读确认。
   - **移动端必测 2 档**：`390×660`、`360×800`，横向溢出严格 `= 0 px`，表单输入框字号 `≥ 16px`。
   - **防假底与交互状态必验**：严禁首屏固定封顶（如 `980px`）与下屏大上留白叠加出纯白死缝（假底效应 False Floor）——须采用「全分辨率露头窥视（`calc(100vh - 140~150px)`＋下屏顶对齐与紧凑上距 `≤36px`）」使下屏真实标题在全部 5 档桌面首屏自然露头，或采用真无封顶 `100vh` 贴底＋下探导引；同步验真透明悬浮顶栏首帧零蓝闪、中段滚动防重叠、搜索联想浮层不被裁切、全页滚扫触发 `loading="lazy"` 后核验破图数。
2. 必过硬门槛：正文与次要文字对比度全部满足 WCAG ≥ 4.5:1；字号种类收敛、同级眉题/卡片/提示条样式统一；图片按显示宽度 2 倍导出 WebP、背景视频转码 ≤6 MB 并预加载封面；核心内容与结构化数据 100% 直出在初始 HTML 内；禁词、商标合规与品牌口径零违规。
3. **交付**：《整页视觉与兼容性体检报告》及修完后的终稿原型。

### 阶段 5：行为闭环切片与研发开工交接
1. 按账户级行为闭环切片法（每片必含 6 要素：可观察行为变化、代码边界、排除范围、验收方法、审查重点、前置依赖）拆解开发包：
   - **切片 0（阻断缺陷热修，不跑 AB）**：死点击、布局撑破、表单漏打分、埋点缺失、非首屏阻塞脚本减负。
   - **切片 1（核心体验改版，走 50/50 服务端无闪烁 AB）**：新版页面结构、交互与埋点。
2. 编写《研发开工交接单》（模板见 [qa-and-ab-playbook.md](qa-and-ab-playbook.md)）：重点写清「看设计稿看不出来但必须做」的项——统一 CSS 规格重写、键盘无障碍、动态取数降级契约（如涉及全库料号必抽检至少 20 个主力类目）、HubSpot 7 个来源隐藏字段与 AI 打分接入、新埋点事件与线上在测实验隔离红线。
3. 重要项目在交开发前过一轮独立交叉复核（核对代码/需求一致性）。
4. **🔴 闸口 G4（人工确认）**：负责人确认研发排期、隔离红线与开工交接。

### 阶段 6：分层灰度验证与规则回流
1. **上线严禁直接覆盖老版本**：英文主站服务端渲染层按 `track_id` 50/50 无闪烁分流，保留 Bucketeer 一键回滚。
2. 按样本量选验收模型（详见 [qa-and-ab-playbook.md](qa-and-ab-playbook.md)）：
   - **大样本页面（首页、导航、桌面详情页等）**：采用「**三层分工制**」判胜（第一层主裁判区显著胜出 ＋ 第二层旁路护栏区不掉坑 ＋ 第三层公司总账区 4 分+ 询盘净增）。
   - **小样本页面（如移动端详情页）**：采用「**14 天 50/50 无闪烁护栏灰度**」（SRM `p > 0.01` ＋ 0 新增报错 ＋ 上游复合意向正向 ＋ 真单下限不低于旧版 80% 即全量，再用 28/60 天 CrUX 与 GSC 排名跟踪长期收益）。
3. **Skill 进化回流**：本轮页面改版结案后，另开干净窗口按 [friction-review-template.md](friction-review-template.md) 扫描本轮原始对话日志提取摩擦点、按四分流更新本 Skill 或 `references/`，不把单页特例塞进主流程。

## 三、12 条防返工硬红线（每阶段自检，违反即拦截）

1. **数据大于主观**：无数据依据不拍板；意见冲突按数据辩论，同意也须附依据。
2. **自有埋点优先**：行为数据用 lily 自有埋点（剔爬虫、拆设备），不用 GA4 替代；Clarity 只补体验信号。
3. **真实可视高度与大屏防假底**：PC 端必验 `2560×1320`、`1920×1080`、`1920×920`、`1440×900`、`1366×768` 五档，小屏不裁切核心行动按钮，大屏绝不在首屏底沿留出 >40px 无内容的纯白死缝（假底效应）。
4. **合标对标门槛**：美国谷歌月自然流量 > 2 万＋模式相同（McMaster/MISUMI 点名放行）；只给网址不发截图；不学电话入口。
5. **设计稿零干扰**：HTML 原型本体不放解说标签、浮窗和占位提示字；说明另存 `_说明.md`。
6. **黄色按钮唯一性与品牌饱和度锁**：`#f7c542` 黄色按钮全站 **100% 独占**留给核心询盘提交入口（`Request a Quote`），严禁挪给搜索、播放或次要按钮；其他衍生控件必须锁在 LILY 中低饱和工业色域内，禁跨色域硬塞高饱和消费科技蓝或霓虹色。
7. **纯 To B 制造厂调性与认证商标合规**：禁用小卡车图标、包邮促销腔（`Free US shipping`）与多余 `Factory Direct` 标签；严禁盗用 ISO、SAE/IAQG、IATF 官方绿地球商标，认证徽标须合规定制或经发证机构书面授权并亮出真实发证方。
8. **品牌与型号铁律**：卖的是 LILY 自有品牌，他牌仅作互换对标（用 `equivalent`，禁写 `genuine`）；型号命名与精度只认品牌官网原文。
9. **美式英文有据可查**：关键英文措辞必核美国 GSC 搜索词或客户留言语料；拿不出写「未核实」；主标题采用正面制造表达（禁用「Not a reseller」式否定防御开场），严禁把内部占比统计（如 95% 线下询盘）泄露为对外产品文案。
10. **组件统一、语义纯粹不堆入口**：页头/页脚全站统一；搜索框下方不混放类目导航词（热门型号收进聚焦联想面板）；页面底端不与自带黄色按钮的页脚及右下角 AI Chat 重复堆叠询盘白卡。
11. **SEO 与表单链路完整**：核心内容与结构化数据 100% 直出初始 HTML；所有新表单必带 7 个来源隐藏字段并验通 HubSpot AI 打分与销售路由。
12. **上线隔离与回滚**：严禁覆盖老版直接全量；严禁污染桌面/移动端其他在测实验。
