## 二、行为闭环切片与研发开工交接单模板（阶段 5 必备）

复杂改版严禁一次性混在一起开发，必须切分为 **切片 0（阻断热修，不跑 AB）** 和 **切片 1（核心重构，跑 50/50 服务端 AB）**。每个切片必须写齐 **6 要素**：
1. 用户／系统可观察行为变化
2. 代码与文件边界
3. 明确排除范围（**必须单列线上在测实验隔离清单**）
4. 验收方法（具体视口、真页 URL、BigQuery/HubSpot 核验动作）
5. 审查重点（最易出回归或污染的风险点）
6. 前置依赖

### 研发开工交接单固定 6 节结构
1. **置顶红线**：① 上线严禁覆盖老版，必须 50/50 服务端无闪烁 AB（写明 Bucketeer 实验名与分流键 `track_id`）；② 绝对不触碰的线上在测实验清单及对应 JS/DOM 名单；③ 仅英文主站（`en-us`）先行，不动多语言表单。
2. **前端与视觉契约**：锁定色板、组件三态（中国仓/美仓/无价）、吸顶/抽屉交互、初始 DOM 要求。
3. **后端、表单打分与性能减负**：所有新表单必须带 7 个来源与访客隐藏字段、接入 HubSpot AI 打分与销售路由并命名规范（禁用“联调”字样）；非首屏阻塞脚本异步/按需加载。
4. **动态数据取数契约（若涉多类目/全库料号）**：必须写明多级降级规则（如 L1 Top 20 精调白名单 → L2 规则滤空 → L3 表头清洗与同义去重 → L4 兜底＋短标签映射），并实检至少 20 个主力类目真实商品防脏数据。
5. **埋点契约（接入 `dwd_quick_tracking_event_slim`）**：补齐本轮核心交互事件、真实性能 `web_vitals`（LCP/INP/CLS）及支付设备归属 `client_platform`。
6. **上线前必过测试清单 ＋ 放量/回滚门槛**。
