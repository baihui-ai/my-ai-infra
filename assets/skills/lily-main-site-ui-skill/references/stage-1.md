### 阶段 1：多源底数诊断与用户画像（禁止先画图）
1. **拉取同口径底数**：
   - `lily` 自有埋点（BigQuery `dwd_quick_tracking_event_slim`，剔除机器与机房流量，**严格拆桌面端/移动端、拆美国/非美国**）：查进站流量来源、首屏/各区块点击分布、站内搜索占比、去向路径、表单/Chat/加购/实付真单转化。
   - `Clarity`（同期同设备）：查死点击、狂点、快速返回、滚动深度，定位需看录屏的具体卡点（⚠️ **调用铁律**：Clarity `query-analytics-dashboard` 每次只能查**单个指标**，多指标合并会触发 `HTTP 500`；查根域名首页 `https://www.lily-bearing.com/` 时勿直接做 URL 过滤［会被当成全站前缀匹配］，须查 `Top 50 visited URLs with dead clicks / quick backs` 排行表再精确取首页那一行）。
   - `GSC`（近 28 天）：查该页自然搜索展现、点击、CTR、平均排名及词类结构（品牌词 vs 品类词 vs 型号词）。
   - `HubSpot` / 客户来信语料（按需）：回答「**来这个页面的人手里拿着什么、最常问什么**」。
   - `线上源码与性能`（`get_page_seo` / `get_page_html`）：核对 H1、结构化数据、脚本体积、移动端/桌面端 DOM 结构与明显阻断 Bug。
2. **因果与样本核查**：严防幸存者偏差（如只看留了邮箱的人忽略未转化流失访客）和因果倒置（如把“落地页差导致广告收预算”误判为“品类没流量不值得做”）。
3. **交付**：《底数对账与问题诊断单》（把问题明确切分为 **P0 阻断缺陷** vs **体验与转化结构问题**）。
