# 关系模型：在线商城系统 · C4 Container 图

- 图类型：C4 Level 2 — Container Diagram
- 范围：在线商城系统及其用户、外部依赖
- 风格：科技炫酷风（tech）
- 非交互运行说明：skill 第 5 步本应询问风格，用户已在任务中指定「科技炫酷风」；协议/职责中未显式给出的部分按行业常规假设处理，逐条标注如下。

## 节点

### Person（边界外）
| 名称 | 类型 | 职责 |
|---|---|---|
| 商城用户 | Person | 通过微信小程序或浏览器访问商城 |

### Container（System Boundary：在线商城系统 内）
| 名称 | 技术栈 | 职责 |
|---|---|---|
| Web 前端 | React SPA | 商品浏览、购物车、下单页面 |
| 商城 API 服务 | Java Spring Boot | 订单、支付、物流业务逻辑 |
| 业务数据库 | PostgreSQL | 商品、订单、用户数据（圆柱体绘制） |
| 缓存 | Redis | 热点数据缓存（圆柱体绘制） |

### 外部系统（边界外）
| 名称 | 类型 | 职责 |
|---|---|---|
| 微信支付 | External System | 支付下单与结果回调 |
| 顺丰物流 | External System | 运单创建与物流轨迹查询 |

## 关系（含协议标注；标注「假设」者为行业常规推断，非用户提供）

| # | 从 → 到 | 意图 | 协议/技术 | 备注 |
|---|---|---|---|---|
| 1 | 商城用户 → Web 前端 | 浏览商品、提交订单 | HTTPS | 渠道（小程序/浏览器）已在 Person 职责注明 |
| 2 | Web 前端 → 商城 API 服务 | 调用业务 API | JSON/HTTPS | 假设（常规前后端协议）；核心链路，青色发光强调 |
| 3 | 商城 API 服务 → 业务数据库 | 读写商品/订单数据 | JDBC | 假设（Spring Boot 常规） |
| 4 | 商城 API 服务 → 缓存 | 读写缓存 | RESP | 假设（Redis 常规协议） |
| 5 | 商城 API 服务 → 微信支付 | 发起支付 / 接收回调 | HTTPS/REST | 假设（微信支付的公开接入方式） |
| 6 | 商城 API 服务 → 顺丰物流 | 创建运单 / 查询轨迹 | HTTPS/REST | 假设（顺丰开放平台常规接入方式） |

## 布局

- System Boundary 虚线大框居中，含 4 个 Container（前端上、API 中、两圆柱下）。
- Person 在边界左侧；两个外部系统在边界右侧。
- 主流向自上而下：用户 → 前端 → API → 数据库/缓存；API 向右出边界到外部系统。
- 图例在底部：用户（紫描边）/ 容器 / 圆柱=数据库缓存 / 外部系统（灰）/ 核心链路（青发光）/ 虚线=系统边界。
