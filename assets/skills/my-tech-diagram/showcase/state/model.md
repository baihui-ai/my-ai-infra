# 订单状态图 · 关系模型

图类型：UML State Diagram（状态机图）。对象：订单（Order）的生命周期。

## 节点

| 节点 | 类型 | 说明 |
|---|---|---|
| ●（无名） | Initial 初态 | 订单创建后进入待支付 |
| 待支付 | 状态 | |
| 待发货 | 状态 | |
| 已发货 | 状态 | |
| 退款中 | 状态 | |
| 已完成 | 状态（终态） | 无出边 |
| 已取消 | 状态（终态） | 无出边 |
| 已关闭 | 状态（终态） | 无出边 |

## 转换（实线箭头，标注 = 触发事件）

| 源 | 目标 | 触发事件 | 路径属性 |
|---|---|---|---|
| Initial | 待支付 | （创建订单，无事件标注） | 主流程 |
| 待支付 | 待发货 | 支付成功 | 主流程 |
| 待发货 | 已发货 | 发货 | 主流程 |
| 已发货 | 已完成 | 确认收货 | 主流程 |
| 待支付 | 已取消 | 超时取消 | 异常路径 |
| 已发货 | 退款中 | 申请退款 | 异常路径 |
| 退款中 | 已关闭 | 退款成功 | 异常路径 |

## 布局决策

- 主成功路径横向贯通（左→右）：Initial → 待支付 → 待发货 → 已发货 → 已完成。
- 异常/取消状态放下方一行：已取消（待支付下方）、退款中（已发货下方）→ 已关闭。
- 初态在左上、终态在右侧与右下，符合状态图布局惯例。
- 终态（已完成/已取消/已关闭）用双线边框区分，图例说明；不引入 ◎ Final 伪节点（三个终态语义不同，各自保留状态框更清晰）。
- 主流程连线用强调色（蓝 #2563EB），异常路径用灰色。
