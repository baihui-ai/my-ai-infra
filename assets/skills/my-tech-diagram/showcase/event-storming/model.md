# 电商下单流程 · 事件风暴图关系模型

- 图类型：事件风暴图（分组式领域事件图，唯一默认布局模式；不画任何连线，空间位置即关系：命令在左、事件在右成对平铺）
- 风格：简洁风（minimal），用户指定；事件风暴默认可推荐便签风，用户已明确简洁风，从其指定
- 范围：买家提交订单 → 支付成功发货 / 库存不足失败，全流程
- 来源：全部内容来自用户描述，无编造元素

## 参与者（Actor）

| 参与者 | 关联命令 |
|---|---|
| 买家 | 提交订单 |
| 仓库管理员 | 通知仓库发货（接收发货通知） |

## 外部系统（External System）

| 外部系统 | 说明 |
|---|---|
| 支付宝 | 支付已成功事件的来源 |

## 分组与命令/事件对

### 分组 1：订单

| 命令（动宾） | 事件（名词 + 已 + 动词） | 备注 |
|---|---|---|
| 提交订单 | 订单已提交 | 参与者：买家 |
| 创建订单 | 订单已创建 | 库存充足分支 |
| 创建订单 | 订单创建失败 | 库存不足分支（一个命令两个事件，向右并列展开） |

### 分组 2：库存

| 命令 | 事件 | 备注 |
|---|---|---|
| 校验库存 | 库存充足已确认 | 分支结果一 |
| 校验库存 | 库存不足已确认 | 分支结果二 |
| 扣减库存 | 库存已扣减 | 支付成功后触发 |

### 分组 3：支付

| 命令 / 外部系统 | 事件 | 备注 |
|---|---|---|
| 发起支付 | 支付已发起 | |
| 支付宝（外部系统） | 支付已成功 | 支付结果由外部系统回传 |

### 分组 4：发货履约

| 命令 | 事件 | 备注 |
|---|---|---|
| 通知仓库发货 | 发货通知已发送 | 参与者：仓库管理员（接收方） |

## 命名检查

- 事件全部为「名词 + 已 + 动词」完成式：订单已提交、订单已创建、订单创建失败（失败即结果事实）、库存充足已确认、库存不足已确认、库存已扣减、支付已发起、支付已成功、发货通知已发送。
- 命令全部为动宾结构：提交订单、创建订单、校验库存、扣减库存、发起支付、通知仓库发货。
- 无技术味命名。
