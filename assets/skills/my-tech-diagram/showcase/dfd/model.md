# 关系模型：order-processing-dfd（DFD / Level 0）

## 图类型
数据流图（DFD），Yourdon-DeMarco 记号：Process=圆形，Data Store=开口矩形（含 ID 格），External Entity=矩形，Data Flow=带数据名标签的箭头。

## 节点

| 编号 | 名称 | 类型 | 说明 |
|---|---|---|---|
| — | 买家 | External Entity | 系统边界外，订单数据来源 |
| 1.0 | 订单处理 | Process | 动宾名（处理订单）；有进有出 |
| D1 | 订单库 | Data Store | 订单数据归宿 |
| D2 | 库存库 | Data Store | 库存数据来源（被读取） |
| — | 支付网关 | External Entity | 系统边界外，支付指令归宿 |

## 数据流

| # | 从 | 到 | 数据名标签 | 备注 |
|---|---|---|---|---|
| F1 | 买家 | 1.0 订单处理 | 订单数据 | 用户提供 |
| F2 | 1.0 订单处理 | D1 订单库 | 订单记录 | 标签为假设（见下） |
| F3 | D2 库存库 | 1.0 订单处理 | 库存信息 | 读取方向 Store→Process；标签为假设 |
| F4 | 1.0 订单处理 | 支付网关 | 支付指令 | 用户提供 |

## 硬性规则核对
- 无 Entity↔Entity / Entity↔Store / Store↔Store 直连，全部经过 Process ✔
- Process 1.0 有进（F1、F3）有出（F2、F4）✔
- 每条 Data Flow 均有名词式数据名标签 ✔
- 单 Process 单层级，无分层编号一致性问题 ✔

## 自行决定项（非交互运行，skill 要求确认处自行合理决定）
1. **Process 编号**：用户未给编号，单 Process 无分层，按惯例定为 `1.0`。
2. **F2 数据名标签**：用户只说「写入订单库」，未给数据名，定为「订单记录」（假设）。
3. **F3 数据名标签**：用户只说「读取库存库」，未给数据名，定为「库存信息」（假设）。
4. **Data Store 编号**：D1=订单库、D2=库存库（编号为图上标识惯例，非业务信息）。
5. **风格**：用户指定简洁风（minimal），不再询问。
