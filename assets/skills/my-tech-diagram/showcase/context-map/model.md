# 关系模型：电商限界上下文映射图（ecommerce-context-map）

图类型：限界上下文映射图（Context Map），版式：分带卡片式（横向分带 = 子域分类）。

## 节点（Bounded Context / 外部系统）

| 中文名 | 英文名 | 子域分类 | 职责 | 所在分带 |
|---|---|---|---|---|
| 订单上下文 | Order Context | 核心域 Core | 订单全生命周期管理 | 核心域 |
| 定价上下文 | Pricing Context | 核心域 Core | 报价与折扣计算 | 核心域 |

| # | 上游 U | 下游 D | 模式 | 中文标注 | 线色类别 |

## 布局

- 三条横向分带（自上而下）：核心域 → 支撑域 → 通用域；左侧带名 + 定位语。
- 列对齐：定价/用户在左列，订单/库存在中列（上下对齐，库存→订单垂直向上箭头），权限在右列。
- 支付宝置于分带之外右侧（虚线边框，标注 External），ACL 箭头由支付宝指向订单。
- 权限→订单的 CF 线走横平竖直折线，绕开其他连线。
- 图例置底部：线色语义 + 箭头方向说明。

## 假设与说明

- 用户已给出全部上下文、方向与模式，无假设项。
- 「订单→支付宝 防腐层」按 DDD 语义解读为：支付宝是上游（其接口变化迫使订单侧适配），订单为下游并自建 ACL 翻译层；图中箭头按「影响方向」由支付宝指向订单，ACL 梯形标在订单一侧。
