# 关系模型：报销审批活动图（expense-approval-activity）

- 图类型：UML 活动图（带泳道）
- 风格：简洁风（用户指定）
- 泳道：申请人 / 主管 / 财务（三条纵向泳道，从左到右）

## 节点

| 节点 | 类型 | 泳道 | 说明 |
|---|---|---|---|
| start | Initial Node（实心圆） | 申请人 | 唯一起始 |
| submit | Action「提交报销单」 | 申请人 | |
| mgr-decide | Decision「主管审批」 | 主管 | 守卫：[通过] / [驳回]，互斥完备 |
| fin-decide | Decision「财务复核」 | 财务 | 守卫：[通过] / [驳回]，互斥完备 |
| pay | Action「打款」 | 财务 | |
| notify | Action「通知申请人」 | 申请人 | 两条驳回路径的公共汇入点 |
| end-pay | Final Node（牛眼） | 财务 | 打款后结束 |
| end-reject | Final Node（牛眼） | 申请人 | 通知后结束 |

## 边（控制流，实线箭头）

| # | 从 → 到 | 守卫 | 路径规划（无交叉设计） |
|---|---|---|---|
| 1 | start → submit | — | 申请人泳道内垂直向下 |
| 2 | submit → mgr-decide | — | 水平向右（主流程，蓝色） |
| 3 | mgr-decide → fin-decide | [通过] | 水平向右（主流程，蓝色） |
| 4 | fin-decide → pay | [通过] | 财务泳道内垂直向下（蓝色） |
| 5 | pay → end-pay | — | 财务泳道内垂直向下（蓝色） |
| 6 | mgr-decide → notify | [驳回] | 菱形底部 → 向下 → y=456 水平向左汇入 notify 右缘（不与主流程交叉） |
| 7 | fin-decide → notify | [驳回] | 菱形右端 → 右外侧通道 x=1190 → 下缘通道 y=640 → 左缘通道 x=140 → 汇入 notify 左缘（全程走外侧通道，零交叉） |
| 8 | notify → end-reject | — | 申请人泳道内垂直向下 |

## 无交叉论证

- 主管驳回（边 6）：主管泳道内空区下行，y=456 横线只跨空区，进 notify 右缘。
- 财务驳回（边 7）：若直接下折会穿过「打款」节点与「打款→结束」连线，故改走右缘 → 下缘 → 左缘三条外侧通道；下缘 y=640 低于全部节点（最低节点 end-reject 底部 568），不与任何节点/连线相交。
- 两条回流汇入同一节点 notify：分别从右缘（边 6）与左缘（边 7）不同方向汇入，互不重叠。
