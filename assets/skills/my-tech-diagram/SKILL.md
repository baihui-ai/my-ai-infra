## 本项目适配（优先于下文默认条款）

本 Skill 源码与所有参考图已内置，由 assets/skills/my-tech-diagram 统一维护。SDD 场景遵循[文档与图示规范](../my-create-feature/references/technical-docs.md)，优先把图放到技术方案实际目录的 diagrams/。先生成完整静态 SVG，再按[动画约定](references/animation.md)生成可播放、暂停、逐步查看的同名 HTML；动画不替代静态图和语义验收，不给领域事件便签添加因果箭头。所有依赖均从当前安装目录解析，不读取维护者主目录。

# my-tech-diagram

用大模型先整理关系模型，再手写 SVG。保留已有业务结论，不编造实体、事件、依赖或多重性。不用 Mermaid、PlantUML、Graphviz 等生成器代画；浏览器和图像工具可用于预览、测量及检查手写 SVG。

## 交付约定（先于通用画法）

这是用户已确认的默认表达，优先于 reference 中的方法论背景与旧 showcase：

- **同一设计的领域模型只交付一张完整图**。即使涉及多个领域/限界上下文，也在同一 SVG 中分区呈现，保留已确认的跨区关系和各区语义；不拆成多张图，不额外生成局部详图，也不用上下文映射图替代实体关系总览。不能为凑一张图删节点或关系。节点数量不是拆图条件。
- **领域模型只画类型与关系**：默认双语卡片，上行英文类型名、下行中文业务名，不画字段或方法。明确区分领域/上下文分区与聚合边界。
- **领域事件图/事件风暴图只交付一张按领域分组的完整图**。默认便签风：黄命令、绿事件、粉色分组标题；同领域内容聚在一块，命令左、事件右按真实对应关系平铺，查询可单贴；定时/外部事实引发的独立事件允许在事件列单贴并标明触发来源。组内、组间均无连线，不按时间轴排成流程图。
- **先核验事件语义再画便签**：读取 `references/event-semantics.md`（本轮一次）。命令是“创建订单”；事件是“订单已创建”；状态“待支付”、查询响应与缓存/重试日志不默认作为业务事件。不得把所有便签都改成动宾结构，也不为成对排版补造事件。
- 用户明确指定其他视觉风格时可换外观，但分组、内容、命令事件配对和无连线规则保持一致；只有明确要求改变表达方式才改变结构。
- 同一设计的各图共用业务名称、范围与稳定 ID。关系模型中记录对应关系；不能在另一张图重新命名同一对象或悄悄改变边界。

## 工作流程

1. **选类型并按需读取**：只读下表对应的 reference；DDD 只读当前图型的小节。明确图类型时不必先读 overview。
2. **核对事实**：先从用户提供的对话、代码或文档补齐最小信息。缺影响业务含义的关键信息才暂停并列出缺口；不能因布局、配色尚未指定而阻塞。没有资料时不凭空出图；只有用户明确允许按假设画，才逐条标注假设后继续。
3. **查看样图**：同一轮工作中同一张参考图只需查看一次；内容未变化时复用，避免每图重复加载。领域模型必须查看 `assets/domain-model-cn-er.jpg`；领域事件必须查看 `assets/event-storming-cn-grouped.png`。路径相对于本 SKILL.md 所在目录，用可用的图像查看工具实际打开，不能只读文件名。借鉴结构、配对和分组，不复刻样图里的业务内容、长英文断词、过小字号或过多空白。若无法查看，说明限制并按文字约定继续，不能声称已经看过。
4. **生成关系模型与布局计划**：保存 `diagrams/<图名>.model.md`，含来源、范围、节点 ID/类型/分组、关系/多重性或命令事件配对、预期节点数/关系数、画布尺寸、分区位置、行列与连线路由。事件图记录配对，不生成连线路由。事实完整时直接继续；不因超过 15 个节点额外要求确认。
5. **选风格并手写 SVG**：默认只读 `references/visual-styles.md` 通用规则及“汇报风 reporting”节；领域事件另读便签节，明确指定其他风格才读对应节。同一轮已读内容复用，不逐图重读。先算卡片、文字和分区尺寸，再定画布；密集内容扩大画布或在同图内分区换行，不为固定 16:9 缩小文字。相同类型组件统一尺寸与间距。
6. **核对完整性并渲染目检**：读回并解析 SVG，确认 viewBox、引用、节点与关系/配对数量；再用可用浏览器或 SVG 渲染器预览，检查整体和文字局部，修正重叠、裁切、连线穿字及标签漂移。只读 SVG 源码不等于视觉检查。无法渲染时如实说明“已做结构检查，未完成视觉验收”。
7. **交付**：给出 SVG 预览（环境支持时）及绝对路径链接，简述图型、范围和风格。关系模型作为可追溯中间稿。不自动附加详图、其他图型或多种风格版本。

## 默认风格：所有图面向汇报

默认“汇报风 reporting”：浅底、清楚的标题与分区、克制语义配色、目标展示宽度下可读；既适合文档，也适合直接用于汇报。风格不改变图型语义。

| 图类型 | 汇报版式 |
|---|---|
| 领域事件 / 事件风暴 | 汇报便签版；黄命令、绿事件、粉分组头，整图分组无连线 |
| 领域模型 / ER / UML类图 | 分区卡片，字段细节只放 ER/类图；领域模型仅类型与关系 |
| 时序图（含总体命令交互） | 清晰生命线和消息标签，真实同步/异步、事务与异常分支，保留时序图而非改成流程图 |
| 流程 / 状态 / DFD | 主路径清楚，条件/异常路径可见；按各图的正确记号表达 |
| 业务架构 / 基础组件调用 / C4 / 上下文 / 网络拓扑 / 部署 | 浅底层级分区，边界与关系明确；不默认黑底霓虹 |
| 甘特 / 里程碑 / Roadmap | 清楚的时间尺度、依赖/里程碑与说明，不强凑16:9 |

简洁、Claude暖色、科技、动画、便签仍可显式选择。默认不做动画/光晕/装饰网格，不自动出多风格版本；不能给领域事件图添加流动箭头。保留“单张完整模型与事件图，无局部详图”的交付约定。

## 输出与验收

产物在当前工作目录 `diagrams/`，图名为 kebab-case：`<图名>.model.md` 与 `<图名>.svg`。迭代覆盖同名文件，不新增版本后缀，除非用户要求保留历史。预览截图可放临时目录。

交付前核对：

- 领域模型是一张完整图，所有输入类型出现，跨区关系保留；只有类型/中文业务名与必要角色标记，无字段/方法。
- 领域事件是一张分组图，分组与输入一致，命令/事件对应准确、查询单贴、独立事件触发来源明确；无关系线、箭头、时间轴或流程泳道。
- SVG 中每个节点组标 `data-node-id`，模型关系线标 `data-edge-id`；分组可标 `data-group-id`，用于核对遗漏。装饰线/卡片分隔线不算关系线。
- 名称、边界和配色含义一致，长英文不从词中断开；无重叠或裁切，目标阅读宽度下可读；关键机制图的失败/补偿/降级路径不能因汇报排版被省掉。
- 已分别完成事实/结构检查和渲染后的视觉检查；未完成的部分不得声称通过。
