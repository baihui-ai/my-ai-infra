# 软件技术图调研总览与选型速查

本文件是「画什么图」的路由层：先在这里判断图类型，再去读对应的专项 reference（`ddd-diagrams.md` / `uml-diagrams.md` / `c4-architecture.md` / `pm-and-other-diagrams.md`），最后读 `visual-styles.md` 选风格。不要反过来先读细节文件。

## 一、图的分类地图

软件行业的图可归为六个家族，回答的问题各不相同：

| 家族 | 回答的问题 | 代表图 |
|---|---|---|
| 领域/业务建模 | 业务概念是什么、怎么关联、业务怎么流转 | 领域模型图、事件风暴图、限界上下文图 |
| 静态结构 | 代码/系统由什么组成 | UML 类图、组件图、ER 图 |
| 动态行为 | 运行时谁调用谁、状态怎么变 | UML 时序图、活动图、状态图 |
| 架构视图 | 系统在技术层面怎么落地 | C4 四级图、部署图、网络拓扑图 |
| 流程流转 | 事情按什么顺序经过哪些环节 | 流程图、数据流图、BPMN |
| 项目管理 | 什么时间做什么事、谁依赖谁 | 甘特图、里程碑图、Roadmap |

## 二、选型速查（按用户意图路由）

| 用户说/意图 | 画什么 |
|---|---|
| 「梳理这块业务的领域模型」「实体关系」 | 领域模型图（DDD） |
| 「事件风暴」「梳理业务事件流」「业务流程上有哪些事件」 | 按领域分组的领域事件图（单图、无连线） |
| 「微服务怎么拆」「上下文边界」「服务间依赖关系」 | 限界上下文图 / 上下文映射 |
| 「这个接口的调用过程」「支付超时怎么处理」 | UML 时序图 |
| 「这些类的继承/组合关系」「代码结构」 | UML 类图 |
| 「审批流程」「订单状态流转」 | 活动图（流程分支多）/ 状态图（对象状态变迁） |
| 「系统架构」「上下游系统」「部署拓扑」 | C4 System Context / Container |
| 「这个功能拆成哪些模块/容器」 | C4 Container / 组件图 |
| 「数据库表结构」 | ER 图 |
| 「项目排期」「迭代计划」「发布时间线」 | 甘特图 / 里程碑图 / Roadmap |
| 「数据怎么流转」「数据从哪来到哪去」 | 数据流图 |

判断不了时，用一句话向用户确认「你想表达的是结构、流程还是排期？」，不要猜着画。

## 三、画图通用注意点（与图类型无关）

这些原则在所有专项 reference 里都默认成立：

1. **图是关系的可视化，不是元素的堆砌**。先想清楚「这张图要让人一眼看出什么关系」，再决定布局和连线。元素多时先规划分组与画布；领域模型/领域事件必须保留一张完整图，不按节点数拆图或附加详图。
2. **每张图只回答一个问题**。把架构、流程、状态揉在一张图里是最常见的失败模式。
3. **关系表达遵循图型**：有向调用用箭头与标注；领域模型关联用多重性，无需箭头；分组领域事件图只用空间配对，不画关系线。
4. **布局即信息**：时序类从左到右（时间轴），层级类从上到下（调用/包含），分组边界用容器框显式表达。相关元素就近放置，连线尽量不交叉。
5. **文字可读性优先**：节点内文字不溢出、图在 100% 缩放下所有文字 ≥ 12px、中英文混排预留宽度。宁可放大画布不要缩小字号。
6. **图例（legend）**：使用非显而易见的颜色/形状语义时（如事件风暴的彩色贴纸），图上必须带图例。
7. **粒度一致**：同一张图里的元素应处于同一抽象层级（如 C4 不允许 Context 图里出现容器细节）。

## 四、关系类型速查

不同图家族使用的关系词汇不同，但底层只有几种，生成关系模型时用这套词汇统一描述，再映射到各图的视觉约定：

| 底层关系 | 语义 | 在各类图中的形态 |
|---|---|---|
| 包含/组成 | A 由 B 构成 | 聚合→实体、系统→容器、类组合（实心菱形） |
| 关联/引用 | A 知道 B | 领域模型关联线（带多重性）、类关联、ER 关系 |
| 调用/消息 | A 请求 B 做事 | 时序图消息、C4 关系线（标协议）、数据流箭头 |
| 触发/产生 | A 发生后产生 B | 领域事件图：命令/事件空间配对，不画箭头 |
| 依赖/先于 | A 依赖 B 完成 | 甘特依赖箭头、UML 依赖虚线 |
| 继承/实现 | A is-a B | 类图泛化（空心三角）/ 实现（虚线空心三角） |
| 上游/下游 | B 变化影响 A | 上下文映射 U/D 关系、系统架构上下游 |

## 五、两段式生成的关系模型格式

第 4 步产出的 `diagrams/<图名>.model.md` 建议结构（可按图类型裁剪）：

```markdown
# <图名> 关系模型
- 图类型：事件风暴图  风格：简洁风  日期：YYYY-MM-DD
- 这张图要回答的问题：<一句话>

## 节点
| ID | 名称 | 类型 | 分组/泳道 | 备注 |
## 关系
| 从 | 到 | 关系类型 | 标注 |
## 时序/布局提示
- （时间序、分层、泳道安排）
## 假设与存疑
- （用户降级允许假设时逐条列出，否则本节必须为空）
```

门禁要求：「假设与存疑」为空，或用户已显式确认接受这些假设，才允许进入 SVG 生成。
