# my-tech-diagram

画软件技术图并产出本地 SVG 的 Codex Skill。两段式生成（先关系模型、再手写 SVG）、信息不全不画（硬门禁）、按需加载规范、风格可控。

## 使用方式

直接说人话即可触发，例如：

- 「帮我画一张电商下单流程的事件风暴图，用便签风」
- 「画个 C4 Container 架构图，前端 React、后端 Spring Boot、PostgreSQL、Redis，科技炫酷风」
- 「把 Q4 排期画成甘特图」（信息不全时会先给你缺口清单，补齐才画）

产物写入当前目录 `diagrams/`：`<图名>.model.md`（关系模型中间稿）+ `<图名>.svg`（最终图）。

## 图类型与默认风格

| 家族 | 图类型 | 一句话用途 | 默认风格 |
|---|---|---|---|
| DDD | 领域模型图 | 同一设计的完整类型与关系；多上下文同图分区，不拆局部详图（双语卡片，无属性方法） | 汇报风 |
| DDD | 事件风暴图 / 领域事件图 | 按领域分组盘点命令与事件（**不画连线、不表达流程顺序**——要顺序请画流程图） | 汇报便签风 |
| DDD | 限界上下文图 / 上下文映射 | 上下文间的集成模式与上下游（分带卡片式：核心/支撑/通用域三条横带） | 汇报风 |
| UML | 时序图 | 运行时谁调用谁（同步/异步/返回值） | 汇报风 |
| UML | 类图 | 类的属性方法与六种关系（组合/继承/关联…） | 汇报风 |
| UML | 活动图 | 带分支与泳道的业务流程（连线零交叉） | 汇报风 |
| UML | 状态图 | 对象状态变迁（状态穷举 + 触发事件） | 汇报风 |
| UML | 用例图 | 参与者与系统功能的边界 | 汇报风 |
| 架构 | C4 架构图 | System Context / Container / Component 三级下钻 | 汇报风 |
| 架构 | 网络拓扑 / 部署图 | VPC/子网/可用区内的组件与链路 | 汇报风 |
| 项目管理 | 甘特图 | 任务排期 + 依赖 + 里程碑（自动 CPM 关键路径） | 汇报风 |
| 项目管理 | 里程碑图 / Roadmap | 季度级方向与关键节点 | 汇报风 |
| 数据 | ER 图 | 表结构与基数（crow's foot 记号） | 汇报风 |
| 流程 | 流程图 | 判断分支与流转（连线零交叉） | 汇报风 |
| 流程 | 数据流图 DFD | 数据在加工/存储/外部实体间的流动 | 汇报风 |

所有图默认采用“汇报风 reporting”，以下历史风格示例不改变当前默认；领域事件仍用汇报便签版（黄命令/绿事件/粉分组，无连线）。

可选风格只是兜底——任何时候说「用 XX 风」就换：简洁风 / Claude 风 / 科技炫酷风 / 动画风 / 便签风，五种风格全部图类型通用。示例见 `showcase/<图类型>/<风格>.svg`（每种图 5 张风格示例，附 PNG 预览）。

新版以 SKILL.md 的交付约定为准。历史 showcase 仅供视觉参考，不能覆盖单张完整图、领域事件无连线等规则。DDD 出图前实际查看 assets 参考图片；交付前渲染目检。

## 硬门禁

每种图有「最小信息清单」（见各 references 文件）：缺关键信息时不画图，给缺口清单（缺什么、为什么需要、怎么补）。你明确说「先按假设画」才会降级，且假设会逐条标注在图上。

```
  ddd-diagrams.md     #   DDD 三图
  uml-diagrams.md     #   UML 六图
  c4-architecture.md  #   C4 四级
  pm-and-other-diagrams.md  # 甘特/Roadmap/ER/流程图/DFD/拓扑
  visual-styles.md    #   5 套风格规范 + 通用质量规则

showcase/             # 15 种图 × 5 种风格的示例图（SVG + PNG）
evals/                # 回归用例（以 evals.json 实际内容为准）
```
