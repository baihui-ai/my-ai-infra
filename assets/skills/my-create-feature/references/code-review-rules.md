# Java 代码与风格检查

用于本次 Java/SQL 设计与代码评审，按实际修改范围执行；不扩大成全仓重构。详细规则维护在 [Java 规范](java-dev.md) 和 [交付经验](delivery-lessons.md)，本表用于检查与证据回收。

| 维度 | 评审必须核对的事实 |
|---|---|
| 范围与命名 | 授权模块/作者/排除项与 Git 范围一致；方法单一职责，必要编排合理；名称表达动作/单位/状态，公开字段和框架契约兼容 |
| 类型与风格 | import/简名、控制流花括号及多行块、三项起的具名条件；固定契约用对象，Map/JsonNode 仅必要边界，toMap 保留 NULL/缺失与序列化 |
| HTTP 边界 | Controller 绑定/序列化的标量和模型字段使用包装类；检查缺省值、校验及拆箱，不扩至全部内部方法，不改变二进制与无内容响应 |
| 仓储职责 | SQL 在已有 Repository/Mapper；不新造执行器，仓储不承载业务编排；实际基础接口/查询注解与参数绑定正确，固定映射不靠动态探表 |
| 表与 SQL | 六基础字段有依据；新增/修改字段 COMMENT；合理默认值与必要 NULL/TEXT 例外；单表写入，JOIN 规模和最多五表边界；索引/分页与扫描成本有实际依据 |
| 事务与锁 | 默认无额外事务；必要方法级短事务真实经过代理，复用已有管理器；准备/等待在外，批次边界不拆必须原子操作；锁必要性与约束/租约/失败恢复可解释 |
| 行为保真 | NULL/重复行/精度/时区/排序分页、条件写入及受影响行数、回滚/重试保留；新旧载荷结构、存量记录、前端/预览与异步完整链路兼容 |
| 验证 | 编译/静态/集成与模型桌面决策分开；方言/锁/并发无真实数据库证据时保留待验证，不用旧测试或装配通过冒充业务通过 |

报告分别给出业务正确性和代码风格结论、检查范围、实际位置、必要例外及未验证项。普通风格问题按实际影响定级；测试绿不等于风格已审。关键一致性证据缺失时保留合并条件；评审阶段只写报告，实施修复后按现有流程复评，不改源码制造通过。

正反例：内部按 ID 建索引的 Map 可保留，固定 HTTP 响应的 Map 应换为明确模型；同类调用虽写了注解也未证明新事务生效；三表 JOIN 仍须验证规模；未知时间不填零值；历史合法载荷不能因新解析器失败而变成空任务。非 Java 文档修改不强加 Java 依赖或数据库验证。

## 状态枚举与索引专项评审

涉及状态或查询变更时，按[状态枚举与联合索引](java-dev.md#状态枚举与联合索引)核对：枚举复用、稳定编码/未知值、允许操作/纯转换与Service副作用分界；联合索引实际列顺序、WHERE书写与访问路径区分；范围转IN的等价性、有限规模及真实计划。正例是复用现有状态码枚举并由Service执行有条件更新；反例是在枚举发MQ，或只把条件移到WHERE最前就宣布索引优化通过。

## 状态编码评审补充

按[状态字符串编码](java-dev.md#状态字符串编码)检查新状态是否优先使用明确业务字符串码、数字码例外是否有既有契约依据；核对显式映射、枚举重命名与存量/接口/消息兼容，不能为采用字符串擅改历史协议。
