# 技术文档与图示接入

本项目技术文档的决策、覆盖和交付规范，供技术设计、方案评审及 HTML 审阅版按需使用。项目既有模板决定章节结构，本规范决定内容质量；保留现有 Profile、路径与授权契约。用户当前要求优先，不复制本机绝对路径或公司私有上下文到目标项目。

## 一份有效方案

- 先识别有效需求、当前代码、范围、约束和验收条件，区分现有事实、拟议变更、估算与未知。只澄清影响选择的缺口，不虚构容量、指标、接口或业务事件。
- 每项关键决策回答：为什么现在做及不做后果；有哪些真实可行备选及未选理由；获得什么与牺牲什么；风险如何检测、恢复和回退。简单变更用短决策表，不为四个标题重复全文。
- 复用已有能力，新增复杂度给出当前需求或风险依据。检查实际涉及的旧数据、接口、消息、配置、客户端和版本并存兼容；已识别后续方向明确具体模块边界、接入位置、迁移步骤与验证方式，不预建无实现接口、空菜单或通用平台。
- 一份覆盖记录关联需求/来源、设计、接口/schema、图示或不需图的原因、验收。规则和类型只定义一次，其他章节引用；按变更增量更新，不重写人工批注及仍有效决策。
- 数据设计给出新增表完整 DDL、变更迁移和模型映射；字段、默认值、索引、回填及回退按实际数据库与项目约定说明。六基础字段使用用户已确认的 id、create_time、update_time、create_by、update_by、is_deleted，不套用参考模板中的 created_by/updated_by。
- 接口保持可发现的完整契约：方法/路径、鉴权与数据范围、入出参类型及嵌套结构、必填/可空/默认/枚举/边界、请求响应及失败示例。共用 DTO 定义一次并明确引用，不用省略号隐藏未定义字段。
- 查询明确筛选与组合语义、排序白名单与稳定次序、分页基准/上限/total、空值和非法值处理。长度、容量、批量等限制注明单位、来源和超限反馈，未知值标待确认，不杜撰限制。
- 涉及页面时先保存文字规则再做原型，优先复用已有页面/原型。前端设计与验收覆盖实际非全屏窗口、缩放、长内容、弹窗和表格溢出、完整查看/复制、主要操作可达性；目标视口沿用项目或用户环境，未知尺寸标待确认。全量搜索需明确是检索范围、字段范围、全选还是导出，保留权限、索引和分页保护。
- 上线风险给出实际适用的发布顺序、切换入口、观察项、停止条件、回退动作与数据处置。小改动可简单直接回退，不强制灰度平台或虚构比例。设计走查与实际执行测试分别记录。

## 图示按语义触发

先规划必要图示，再补齐对应事实，图放在解释该决策的章节。复用同一名称、范围和稳定 ID；不为凑图引入组件、实体或事件。

| 实际范围 | 图示与内容 |
|---|---|
| 完整架构方案 | 业务模块/功能架构图、基础组件交互图，分别表达职责和实际基础设施关系 |
| 业务命令/流程交互 | 一张总体时序图，包含实际参与方、同步/异步、提交边界、重要分支和失败返回 |
| 仅简单列表/详情查询 | 完整接口契约即可，不强制流程图或时序图 |
| 领域模型变化 | 一张完整类型关系总览，可同图分区；默认中英名称，领域模型不混入字段/方法，DDL 单独维护 |
| 业务事件变化 | 先列来源、归属、触发和业务结果，再用一张分组事件图；无业务事件则说明并省略，不把重试、缓存日志或查询结果当事件 |
| 业务状态或上下文边界变化 | 适用的状态图或上下文图，标明真实转换与边界 |
| 实质表关系/schema 变化 | 必要的 ER 图和准确 DDL/迁移；单个孤立字段变更不强制加图 |
| 幂等机制 | 展开键/范围、原子判重、并发重复、结果复用、提交、失败重试和过期，不只画“幂等校验”框 |
| 跨库/缓存/索引/消息等一致性 | 展开权威源、事务、传播顺序、部分失败、重试/补偿/对账 |
| 缓存新增或变更 | 展开命中/回源/回填、写入失效、过期、并发旧值回填和故障降级，说明不适用路径 |

一张图能清楚覆盖多个机制时复用；拥挤时按机制分图，不机械按命令逐个出图，不设置固定图数上限。

## 画图能力适配

1. 默认使用随本包安装的 [my-tech-diagram](../../my-tech-diagram/SKILL.md)，读取入口及当前图型所需参考并调用内置动画脚本；相关源码、样图与评测统一由本仓库管理。用户明确指定其他工具时再适配，不依赖维护者电脑上的技能目录。
2. 用户指定其他绘图插件时按该插件真实能力处理，复用同一事实模型，不对同图重复调用多个工具生成版本。集成约定不等于安装插件，也不自动安装插件或连接远端服务。
3. my-tech-diagram 的领域事件图采用单张分组便签、黄命令/绿事件/粉标题，不画连线和时间轴；实际因果顺序由总体时序图表达。命令是意图，事件是有来源的已发生业务事实；拟议事件标为拟议。
4. 图资产保存到技术方案实际目录下的 diagrams/，使用相对引用；存在项目图路径约定或插件固定输出位置时，在方案中记录真实位置并维护有效相对链接，不移动或覆盖无关文件。保留事实/关系模型和生成资产，增量修改受影响图。
5. 无指定可用绘图能力时，可用项目已有 Mermaid/手写 SVG 能力表达同一语义；无法完成则保留准确文字、图示覆盖与待完成项，不宣称已出图或通过视觉验收。
6. 检查图与正文/代码/DDL 一致，并实际渲染检查重叠、裁切、文字和路径。结构检查、视觉检查分别报告，本地 Markdown 与 HTML 中的图示必须实际可读。
7. HTML 转换复用已有图资产和语义，不另造一套事件/模型图；领域类型关系图与数据库 ER 图明确区分。图片及引用安全处理，不执行来自图资产的任意脚本。

## 本地文档交付

模板与路径遵循本项目共享阶段契约：PRD、技术方案和测试计划使用本项目 templates/mai-specs 中的标准模板，简版使用对应阶段 Skill 的模板；已有项目覆盖按契约优先。产物保存于当前 Feature 的本地目录，图示使用相对引用，HTML 审阅版复用同一 Markdown 与图资产。

## 行为验收场景

- 简单查询：接口契约完整，不强制画图；含糊的“全量”语义不私自缩小范围。
- 缓存/幂等/一致性：图展开真实失败和恢复路径，没有对应机制则不凭空添加组件。
- 领域事件：不把查询响应或技术重试当业务事件，不为排版补造事件。
- 非全屏页面：主要操作、长内容查看和弹窗在目标小窗口及缩放下可用，未打开浏览器不报告通过。
- 未安装绘图插件：明确降级结果或待完成项，不伪造插件已集成和远端插图成功。
