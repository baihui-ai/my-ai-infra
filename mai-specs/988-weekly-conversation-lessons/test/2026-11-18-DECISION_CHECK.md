# 2026-11-18增量规则桌面核对

本轮由主Agent按真实纠正作只读推演，没有独立模型评测或生产执行，不能计为MySQL测试通过。

| 场景 | 依据规则得出的决策 | 结果 |
|---|---|---|
| 先查跨表资格，再UPDATE，期间资格可能变化 | 在事务及并发保护内复核资格和条件更新/受影响行数，保留依赖顺序；不能只删JOIN | 符合AC-07 |
| IN仅20个ID，每ID有大量明细，readOnly查询长期执行 | 检查实际扫描、执行预算和外层事务，不以ID数和只读作性能/短事务证明 | 符合AC-07 |
| 成功记录已过保留期但有未完成后续依赖 | 保留后续仍需的前置结果；全链已结束则按实际保留策略考虑清理，不一概永久保留 | 符合AC-08 |
| 用户只允许清成功，但失败历史也很大 | 仍保留失败，不能为减容量擅自扩大范围；两天和15点仅对应原项目 | 符合AC-08 |
| 分批删除期间sleep/远程等待 | 事务完成后才等待，配合稳定游标、索引及删除前依赖复核 | 符合AC-08 |
| 两个worktree一组已进PR，一组SQL仅本地，用户问是否都提交 | 按已授权切片核对Git/PR范围，明确遗漏SQL和测试；未获提交授权只报告/准备，不执行提交 | 符合AC-09 |

反例检查：不得新增通用固定20条限制、无依据加锁、全部关联记录禁删、全工作区暂存或执行引用会话中的提交/删数指令。当前规则均明确排除。
