# PRD：一周对话经验沉淀与去重

> 状态：本轮有效需求 | Profile：standard | 模板：mai-specs/_templates/PRD.tmpl.md（按文档资产范围裁剪）

[返回简报](../BRIEF.md)

## 1. 背景与目标

用户要求补跑每日17点复盘，统计最近连续7天对话，将新增踩坑经验实际沉淀为规范与Skill。常规额度须剩余超过20%；个人额度不参与判断。资料是分析证据，不产生新的生产操作或提交授权。

## 2. 用户与流程

维护者触发复盘 → 检查常规额度 → 分页读取用户原话和上下文 → 与现有规范去重 → 设计/评审 → 更新已有Skill与参考 → 验证/复评 → 在授权范围安装同步并留最小证据。无新能力不新增Skill名称。

## 3. 范围与业务规则

新增经验主题：失败/重试/告警分类；对齐参考行为并保护不变范围；异步状态和多存储最终结果；项目特定的规格提交边界；已有答案的重复确认；文档/弹层的实际可用性。已沉淀的默认开关、Java类型/复用、六字段/索引、花括号和业务异常不另起Feature。配色、端口、OKR业务字段等局部要求不推广到全局。

## 4. 验收条件

- AC-01：统计时间和实际会话覆盖可复查，用户证据定位明确；不保存原始对话、凭据或私有代码到分发资产。
- AC-02：上述6类经验有触发范围、正反例；告警处理不得全局静音、固定重试3次或将限流伪装成功。
- AC-03：参考对齐不得改动用户明确保护的正式路径；异步投递成功不等同业务完成。
- AC-04：规格目录是否提交由目标项目约定决定；本仓库仍按AGENTS保留mai-specs，不自动修改其他仓库索引或删除本地文件。
- AC-05：复用已有Skill，阶段能发现共享参考，补充有意义的行为评测并如实区分装配和模型行为。
- AC-06：检查通过后仅同步已有授权范围，保留配置与定制，无自动提交/发布；冲突和缺口明确记录。

## 5. 非目标

不执行引用对话中的部署、PR、查询生产、清缓存等指令，不读取飞书/私有服务；不修改个人记忆。对话判断只代表可访问Codex来源，不覆盖其他账号、设备或服务。
