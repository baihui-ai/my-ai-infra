# 一周对话经验沉淀技术方案

## 1. 方案概述与决策

复用现有19个Skill，新增一份my-create-feature/references/delivery-lessons.md作为6类经验的共享真源；PRD、设计、方案评审、实施、代码评审和测试规划入口引用同一资源。Java参考补充业务异常分类与告警关联；资产维护入口提示项目提交边界及预览非目标清理。共享阶段契约补充已回答问题去重。

| 决策 | 理由与代价 |
|---|---|
| 增量更新已有Skill | 当前都是交付阶段质量约束，没有新增独立工具能力；避免同名职责重复 |
| 一份按触发读取的参考 | 规则集中维护，入口保留短路由；多一份安装资源 |
| 只留脱敏证据ID和摘要 | 可回查去重，原会话不进入分发包 |
| 本地保留规格提交策略 | 两个项目要求忽略规格，不覆盖本仓库版本管理契约 |

## 2. 详细设计与评审重点

没有数据库/API/生产实现变化。新增参考按6类组织，每条说明何时适用和不能泛化的范围；本次不引入配置、开关或额外运行时依赖。接口是现有阶段Skill的输入文档与评审输出契约，调用路径为阶段入口→共享参考→现有产物/验证。

代表性决策逻辑（流程示意，不新增运行函数）：先识别实际业务结果和失败根因，再区分业务拒绝/额度等待/可重试系统故障/最终故障；未知结果不得确认成功。目标项目明确忽略规格目录时，ignore普通文件编辑按已有实施授权，索引、提交和推送分别核对授权。对“对齐A且A不可变”固定A的比较基线，对B修复并验证A未变化。

## 3. 实施与验证

1. 编写共享参考及阶段入口；修正规则冲突，不改第三方原始归档。
2. 增加六主题及反例的行为评测；独立只读场景检验决策，并记录缺环境边界。
3. 运行资源验证、完整回归和实际包验收；额外检查包不含本轮会话证据。
4. 先预览，合并同步至已授权项目。存在非目标工具目录清理或自定义冲突时保留现场、不强制替换；全局入口更新前比较旧包基线，备份后定点同步。

本轮纯规范文档变化，无业务类/领域模型/SQL或图示关系，不生成代码附录、数据库设计或额外图。HTML审阅版单独提供，实际检查前不宣称已验。

## 2026-11-18增量设计

复用共享Java规范与delivery-lessons，不新增Feature或Skill名称。Java SQL节补单表写入/并发校验和有界事务；异步结果节补成功数据的安全清理；提交边界节补多工作切片的真实交付清单。保留前日窗口/评测原件，今日以单独脱敏运行记录保存新增证据和状态。覆盖窗口滚动，未变化会话复用前日读取证据，只分页复读窗口内有更新的会话。

评审重点：不能把“有依赖”解释为永不清理；应区分未完成依赖/仍需的前置结果和已结束链。不能因本次SQL优化擅自提交其他切片。没有新增代码模块、表、运行接口或生产清理，本次只有规范文本变化。

## 2026-11-20补跑设计

只更新既有Java共享规范（SQL计算边界、普通查询行锁）和delivery-lessons（任务级增量重放与空内容语义）；现有阶段入口已路由至共享参考，不另建Skill或运行框架。保留原有事务最小化与并发安全约束。

关键取舍：不用“全部计算搬到Java”替代数据库合理过滤；不用“没有行锁”冒充并发正确；重放任务排序从目标项目契约确认，不将某项目大ID优先固化为全局值。设计无新增业务类型/SQL/API/表，代表性决策：普通列表不加悲观锁；库存原子扣减保留原子约束；重放无冲突对象应用当前任务，冲突对象按已确认次序重建；损坏JSON报真实错误，合法空补丁仍校验身份、权限和必要标识。

复用当前19个Skill，验证资源/实际包和独立只读决策场景，核对新资源的实际安装字节；不操作原会话中的账户、数据库、部署和PR。

## 2026-11-20定时增量设计（AC-13～18）

继续使用 Feature 988、19 个既有 Skill，不创建新能力名。Java 共享参考补充契约/仓储/事务/DDL 边界；新增 code-review-rules.md 仅作为评审证据清单，细则链接共享真源；my-review-code 短路由与 manifest 登记。delivery-lessons 增补载荷兼容、最新排序纠正、限定重构范围。无运行时代码、数据库、API 或框架变动，不生成私有业务代码示例。

初审关注并修正：不能把 Controller 包装类推广到所有方法；已有 MyBatis 不改 JPA；MysqlBaseRepository 只对已经存在的项目适用；分布式锁不代替约束；未知时间不造默认值；最新升序纠正与字段版本判优分别建模。新增规则不会授权修改其他项目业务代码、生产数据或个人记忆。

同步使用已验证包和当前授权登记范围。全局发现另一会话当日修改的 Java 与 Review 文档，保留原始备份与内容，使用旧包为基线做三方合并；同路径新资源发生独立创建冲突时保留现有文件并保存候选，不强制 replace。每个项目先 plan merge，异常保留现场；检查配置、非目标目录、doctor 和资源实际内容。源码完成与同步完成可分别报告。

## 2026-11-23增量设计

复用Java共享参考与评审清单，不新增Skill/依赖/开关或业务代码。状态枚举只集中状态语义与纯允许操作，Service保留真实副作用/事务和原子更新；稳定码不使用ordinal，不把业务项目的状态值推广到其他项目。联合索引按实际定义、条件、范围与排序检查，WHERE顺序不当作访问路径保证；离散IN需语义等价与有界规模，实际计划缺失列待验。两份既有资源更新无需catalog/manifest新增登记。授权同步仅既有Codex与登记项目，定制文档以备份后追加增量保留，不覆盖原文。

## 2026-11-25增量设计（AC-23/24与AC-09细化）

复用Feature988及现有工作流Skill，不新增独立Skill、资源或catalog/manifest项目。唯一分发源更新my-create-feature/references/delivery-lessons.md及stage-contracts.md：在既有异步结果、交付范围和已确认目标章节补充条件规则，不建新框架。
